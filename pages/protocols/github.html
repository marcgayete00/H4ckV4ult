Github

A web-based platform that uses the Git version control system to help developers store, manage, and collaborate on their code

Everytime you found a repository service or similar checkout the commits sections since you may found deleted passwords or other interesting things

Usage

    Here there are a few commands to use git in terminal in order to perform some actions

    Clone repo

      git clone URL

      You can always clone a ssh repo 

      git clone ssh://bandit27-git@bandit.labs.overthewire.org:2220/home/bandit27-git/repo

    Check log

      Show all changes performed in a repo

      git log

      In case we want to check changes for a specific commit we could do

      git show 710c14a2e43cfd97041924403e00efb00b3a956e

    Show branches

      Show all branches from a repo

      git branch -a

      In case we want to change the branch were we are (Where dev is branchname)

      git checkout dev

    Show tags

      Show all tas of a repo

      git tag

      In case we want to check content of a tag (Where secret is the name of the tag)

      git show secret

    Perform a push

      How to perform a push

      Once you have the file we want to push we will need to add it to the repo

      git add -f key.txt

      Perform a commit with any kind of text we want

      git commit -m "Add key.txt with secret content"

      Just perform the push

      git push origin master

Exploitation

    Dependency chain attack (Typosquatting)

      In case you found a package.json or requirements.txt file you could be able to perform a dependency chain attack. This is a type of supply chain attack that targets the dependencies of a software project. In this attack, an attacker injects malicious code into a dependency that is used by the target project.

      So instead of downloading a legitimate package, the victim downloads a package crafted by the attacker

      Remember the key is the version number so in that case based on the requierements choose a number or other. Here are some examples

      ==: This is the version matching clause. For example, if the requested package is some-package==1.0.0, only the 1.0.0 version would be downloaded. It's important to mention that wildcards can be used, so some-package==1.0.* would also match 1.0.0, 1.0.1, and so on.
<=: This the version matching clause that would match any version equal or less than the specified version. For example, if some-package<=1.0.0 was requested, versions 1.0.0, 0.0.9, and 0.8.9 would match, but 1.0.1 and 7.0.2 would not.
>=: This the version matching clause that would match any version equal or greater than the specified version. This is the opposite of the <= clause.
~=: This is the compatible release clause, which will download any version that should be compatible with the requested version. This assumes that the developer versions the package according to the specification. For example, if some-package~=1.0.0 is requested, 1.0.1, 1.0.5, and 1.0.9 would all match, but 1.2.0 and 2.0.0 would not.
