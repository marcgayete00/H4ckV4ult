    AWS (Amazon Web Services)

    A cloud computing service provided by Amazon that offers a wide range of services including compute, storage, database, and networking capabilities. It allows users to access and manage these resources over the internet.

    Basics

      Service Description
      EC2 Elastic Compute Cloud - provides resizable compute capacity in the cloud
      S3 Simple Storage Service - provides secure, durable, and highly available object storage
      IAM Identity and Access Management - provides secure control over AWS resources

      Just in case you are enumerating a local AWS environment you'll need to modify the /etc/resolv.conf In this file you only need to place the IP of the DNS server

      nameserver 52.206.233.48

      An then perform the query passing the domain name and the IP

      host -t TXT offseclab.io 52.206.233.48

      Another situation you may encontuner is to add a subdomain. In that case ask the DNS server just like this

       dig www.offseclab.io @52.206.233.48 +short

      And then add the new ip to the /etc/hosts obviously providing the domain name

    Usage of AWS CLI

      Defining profiles

        AWS cli works using profiles and credentials stored in the ~/.aws/credentials file.

        You can define a profile by using the following command which will prompt you to enter your credentials:

        aws configure --profile amethyst-admin

        Then check if you done it correctly

        aws sts get-caller-identity --profile amethyst-admin
        Warning: Have in mind that this actions are logged

    IAM

      Basic listing

        aws --profile target iam list-users   #Listing users 
aws --profile target iam list-groups  #Listing groups
aws --profile target iam list-roles   #Listing roles
aws --profile target iam list-policies --scope Local --only-attached 
aws --profile target iam get-account-authorization-details  #Get all information about IAM users (May not work based on permissions but in case it works you may be able to obtain informatin that by other methods you couldn't)

      Automate process

        Pacu tool let us automate the process of enumerating IAM permissions. Just open it, list modules and check for [Category: ENUM]

      Listing policies

        We can attempt to list policies associated with the user or role. Use the following command. If it does not appear any error means that we have the permission iam:ListAttachedUserPolicies action

        aws --profile target iam list-user-policies --user-name clouddesk-plove

      Listing groups and policies based on a user

        In case any group is listed we can deduce that some policies may be inherited since the user belongs to that group

        aws --profile target iam list-groups-for-user --user-name clouddesk-plove

        If we find any group we can check the policies associated with it. There are two types of policies: managed policies and inline policies.

        Managed Policies

          AWS managed policies are designed to provide permissions for many common use cases. They make it easier for you to get started with assigning permissions to users, groups, and roles than if you had to write the policies yourself.

          aws --profile target iam list-group-policies --group-name support
          these policies often grant broader permissions than might be desired. Ideally, they should be paired with other more-restrictive policies to ensure fine-grained permission control.

        Inline Policies

          Inline policies are embedded directly within the user, group, or role and belong exclusively to that principal.

          aws --profile target iam list-attached-group-policies --group-name support

        Now we can check the version of that policy:

        aws --profile target iam list-policy-versions --policy-arn "arn:aws:iam::aws:policy/job-function/SupportUser"

        And finally inspect the policy details:

        aws --profile target iam get-policy-version --policy-arn arn:aws:iam::aws:policy/job-function/SupportUser --version-id v8

        Finally, in case you don't have the privileges to query IAM-related information we can use the module iam__bruteforce_permissions from pacu to identify actions we could perform

      Gather additional information

        We can use the following command to gather account summary information:

        aws --profile target iam get-account-summary | tee account-summary.json

        An important thing to note is the parameter "AccountMFAEnabled": 0 which indicates that Multi-Factor Authentication is not enabled for the account.
